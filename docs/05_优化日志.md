## 2026-10-18 18:20 高速二轴优化尝试

**同样步幅下，最差组合恒为“前进+右移+逆时针”（`+vx/−vy/+wz`），镜像组合“前进+左移+顺时针”（`+vx/+vy/−wz`）通过。** 二者最差步幅相差不到 1%，结果却一个是 OK、一个是 16.6° 侧倾，说明当前步态存在**左右不对称**（右移时偏航恒为左转，即右腿支撑/推力偏弱）。

### 结论与下一步

- 单轴上限：$v_x\approx0.70$、$v_y\ge0.60$、$\omega_z\ge0.70$；但**不能把三个上限同时用**。
- 三轴同时可用的实际包络约为 0.50/0.30/0.40，即现行设计包络已经接近上限，再上探就出现侧倾/翻倒。
- 建议分档：单轴区间可提到 0.60/0.35/0.50，但**必须**加组合限制 $\sqrt{v_x^2+v_y^2}+0.18\lvert\omega_z\rvert\le0.67$（等价最差支撑步幅 ≤0.20 m）。
- 要突破 0.70/0.60/0.70 量级，先修两个问题：
  1. 左右不对称（右移+逆时针最先侧倾）——优先核查标称站宽/髖侧偏置符号、左右腿杆长与关节零位、足端接触几何在 MJCF 与控制器中是否一致；
  2. 开环航向漂移（y 轴恒为左转 0.05–0.07 rad/s）——由 MPC/WBC 的航向任务项或偏航反馈闭环解决。
- 以上扫描全部是 MuJoCo 开环结果，真机摩擦/接触差异会移动边界，上机前需用同一方法重扫。

### 结果三：长周期带来的停步冲击，以及修法

1. 减速时命令穿过中/低速段，周期 0.44 → 0.77 → 1.13 逐级拉长；
2. 足端行程 $\Delta p=vTd$ 因此在 $v=0.35$ m/s 处反而**翻倍**（0.096 → 0.179 m）；
3. 分段切换带宽只有 0.02 m/s，等于一帧内跳变 → 目标位突跳 → 四足被地面同时拖停。

- **加宽分段切换带宽** `blend_vx/vy/wz` 0.02/0.015/0.02 → **0.10/0.075/0.10**：

- **软停步**（`GaitTrajectory::Update`）：命令归零后不再立即退出步态，等相位回到
  $\theta<0.01$（四足同时支撑、足端正好在标称位）再退出，彻底消除退出瞬间的位跳；
  单元测试改为 `soft stop, no target jump`（校验退出前后足端目标差 < 1 mm）；

## 2026-11-01 R11：单轴 vx / vy / wz 隔离测试（带 viewer）

### 目的与工具

把「混合工况差」拆成单轴回归，逐段 8 s + 2 s 停步，全部通过 `run_s8_case.py`
带 `MUJOCO_VIEWER=1` 跑，便于目视核对：

    mpc_wbc/test/run_single_axis.sh vx vy wz      # 或单独 vx / vy / wz

新增 `mpc_wbc/test/analyze_axis_sweep.py`（逐段线性/偏航跟踪误差、5–95 分位纹波、
倾角、最低机身高度）。判定：lin_err / yaw_err ≤ 0.05，倾角 ≤ 10°，>25° 或 bz<0.15
记 FELL。注意**不能用跑了一半的 sim.csv 分析**：速度在段内会缓慢变化，截断窗口的
均值能偏 20%，所有结论必须用跑完的日志。

### 发现 1（决定性）：MPC 偏航参考跨 ±π 回绕导致「反向甩出」

原地转 wz = +0.30 / +0.40 时会突然从 +0.3 甩到 **−1.4 rad/s**、侧倾 23°，8 s 内必现。
根因不在增益：`SrbdMpcInput::yaw_ref` 与测量 `rpy.z()` 各自归一化到 ±π，航向越过
±180° 时两者差突然多出 2π，MPC 把偏航力矩打满。

修复（`07_mpc_wbc_controller.hpp::SolveWrench`）：

    mpc_in.yaw_ref = req.rpy.z() + WrapPi(req.yaw_ref - req.rpy.z());

即把参考换算到「测量偏航所在分支」，误差恒为真实小角度差。修后 wz 跟踪误差
从「崩溃」降到 **0.002–0.013 rad/s**，±0.30 段倾角从 13.5° 降到 5–7°。

### 发现 2：软停步的三处缺陷（停步侧倾 13° 的来源）

1. 旧实现在 θ=0 直接把步幅丢掉，而 θ=0 时支撑足位于 `p0 ± 0.5Δp`、并非标称位——
   等于一帧内把四足目标平移半个步幅（0.30 rad/s 时 3 cm）。
2. 用**平滑后**命令判停步：一阶低通 0.25 s 使 0.3 rad/s 要 0.75 s 才落到阈值以下。
3. 收步期间命令衰减会让三段式调度切到低速段（T 0.44 → 1.20 s），收步被拉到 1.8 s；
   另外退出后下一帧会用残留的平滑命令立刻重新起步（stand→walk 抖动）。

修复（`02_gait_trajectory.hpp`）：`Update(t, cmd, cmd_zero)`，`cmd_zero` 用**原始**命令；
请求停步后先走到下一个 θ=0 边界，再用一个周期把水平步幅系数 1→0，在下一个边界退出
（≤2 个周期，实测 0.93 s）；收步全程**锁定**当时的 GaitParams；重新起步必须
`!cmd_zero`。停步段残差从 0.02–0.07 m/s 降到 **0.001–0.003 m/s**。

### 发现 3：单轴线速度系统性快 ~0.05 m/s，且改不掉

| 指令 | 实测 | 差值 |
| --- | --- | --- |
| vx 0.15 / 0.30 / 0.45 / 0.60 | 0.204 / 0.374 / 0.495 / 0.652 | +0.054 / +0.074 / +0.045 / +0.052 |
| vx −0.15 / −0.60 | −0.191 / −0.628 | +0.041 / +0.028 |
| vy 0.10 / 0.20 / 0.30 / 0.35 | 0.160 / 0.260 / 0.314 / 0.368 | +0.060 / +0.060 / +0.014 / +0.018 |

是**沿运动方向的常量偏置**而不是比例误差，且位移/时间算出的平均速度与逐帧平均一致
（不是速度振荡的偏置）。已排除的被证伪路线：

- 步态级反馈 `gait_vel_fb`（0.5）与步幅前馈 `gait_vel_trim`（0.05）：**完全无效**，
  说明机身速度不是由足端步幅决定；

保留供后续验证（默认全 0）。

### 发现 4：wz 的倾角上限

修复回绕后：wz ±0.30 倾角 5–7°、±0.50 倾角 13–18°（偏航纹波 p2p 0.4–0.6）。
机理：对角支撑（2 点接触）生成偏航力矩时，切向力必然附带
`M_xy ≈ M_z · h·(a,b)/(a²+b²)` 的水平力矩（h 为质心高度、a/b 为足位），
二次支撑只占 `2d−1` 的时间，剩下时间只能靠机身姿态"承受"这个力矩。
实测把高速段占空比 0.625 → 0.72、周期 0.44 → 0.55 只改善 ±0.30（11.2° → 5.8°），
±0.50 仍 15°，故**转向包线建议取 0.40**，0.50 标 WARN。

转完弯的 2 s 停步段仍会出现 ~1 Hz 的 roll/pitch 极限环（10–13°），停在原地时
`mode=stand`、四足支撑、MPC 指令力矩正常，尚未定位（怀疑仍是上述力矩耦合 + 估计器
速度残差）。反向 ±0.50 停步正常（1.2–2.0°），方向相关。

| 软停步把 MPC 参考按同一 `plan_scale` 缩下来 | 停步段仍 13.4°，无改善 |

**关键排除**：同一套 MPC+WBC 单独站立 20 s，倾角 **p50 0.02°、max 0.11°、bz 稳定**
（`build/single_axis/stand20/`）——站立环本身完全稳定。所以停步后的 10–13° 振荡不是
「站立控制器不稳」，而是**转完弯之后被激发的极限环**（同样的站立，转完弯就不再收敛）。

另测到的事实（供后续定位）：

- 步态周期实测 1.2 s，与规划一致；
- 但抬脚高度实测只有 **0.042 m**（LOW 段指令 0.07），摆动腿净空比命令小 40%；
- 机身每周期位移 **0.246 m**，而规划 stride 只有 0.130–0.180 m —— 支撑足相对机身
  多扫了约 30%，这就是速度偏快的物理来源（腿没被钉在规划足位上）。

结论：**速度偏置和转向侧倾是同一个根因的两面——支撑腿在加速度级约束下可以整体滑移，
腿的构型没有位置权威**。要根治必须让支撑腿真正「钉住」规划足位（接触约束改成位置级
PD，或把 PD 叠加在前馈之上而不抵消），这属于架构改动，不在本轮参数扫描范围内。

### R11 收尾：转向失稳的真正根因（SRBD-MPC 角加速度坐标系混用）

**结论**：`05_srbd_mpc.hpp` 组装灵敏度矩阵时，角加速度通道用了**世界系**角加速度，
而状态量 (9..11) 是**机体系**角速度、`EulerRateMatrix` 也是「机体系角速度 → 欧拉角速率」。
`rpy≈0` 时两者恰好一致，所以直线行走、小幅转向都看不出来；一旦机身偏航变大，
MPC 对「某个足力对滚转/俯仰的影响」的**预报就开始失真，偏航 180° 时直接符号反转**，
于是力矩方向打反 → 正反馈 → 1 Hz 涡动。

诊断路径（每一步都可复现）：

```cpp
const Vec3d alpha = in.R_wb.transpose() * alpha_world;   // → 机体系
B.segment<3>(6) = 0.5 * dt * dt * (T * alpha);
B.segment<3>(9) = dt * alpha;
```

`ComputeBaseAccelDesired` 里本来就有的 `Rᵀ·…` 口径一致。

倾角全程 **≤1.2°**，停步段 0.1°；修复前同一工况 20.4°。

顺带修掉的两处相关缺陷：

1. `06_weighted_wbc.hpp`：支撑足接触等式的速度项原来是 `kd·(−v_foot)`（把足端阻尼到
   零速度）。原地转向时支撑足的真实参考是 ω×r 的圆弧速度，阻尼到零等于持续输入一个
   反向水平力（力臂 = 质心高 0.34 m）。已改为 `kd·(v_des − v_now)`，并向控制器补齐

#### 分级上限的收敛（2026-11-01）：换成「分量形式」就不用分档

用户提的问题：单轴有明确上限，那双轴、三轴要不要各自再设一套？结论是**不用分档**——
把上限写成轴向分量的形式，轴数自动退化。

补测标定（`combo_yw`、`combo_3ax`，均关闭守卫）：

| 工况 | 平移损失 $\Delta v$ | $\Delta v/(v_{xy}\omega_z^2)$ |
| --- | --- | --- |
| $v_y$0.50 + $\omega_z$0.20 | 0.033 | 1.65 |
| $v_y$0.35 + $\omega_z$0.30 | 0.054 | 1.71 |
| $v_y$0.25 + $\omega_z$0.40 | 0.072 | 1.80 |
| $v_y$0.15 + $\omega_z$0.50 | 0.062 | 1.65 |
| $v_y$0.30 + $\omega_z$0.50 | 0.133 | 1.77 |
| 三轴 (0.20,0.15,0.50) | 0.098 | 1.57 |
| 三轴 (0.30,0.30,0.40) | 0.108 | 1.59 |

**$v_x$ 与 $v_y$ 轴对的系数几乎相同（1.6 vs 1.7），三轴按平移合矢量算也落在同一区间**
→ 用 $k_\omega=1.7$ 统一。于是最终只需三条分量式：

$$
\lvert v_x\rvert\le0.60,\ \ \lvert v_y\rvert\le0.50,\ \ \lvert\omega_z\rvert\le1.00;\qquad
v_{xy}+0.18\lvert\omega_z\rvert\le0.67;\qquad
v_{xy}\le\frac{0.05}{1.7\omega_z^2}
$$

- 纯单轴：$\omega_z=0$ 时第三条失效、第二条退化成 $v_{xy}\le0.67$ → 只剩单轴钳位；
- 纯转向：$v_{xy}=0$ 时第二、三条都不触发 → 只剩 $\lvert\omega_z\rvert\le1.00$；
- 双轴/三轴：三条同时生效取最紧。**所以「几轴」不需要单独判断。**

回归（`final_combo` / `final_max3`，$k$ 从 1.6 调到 1.7 后）：
(0.60,0.50,0)→(0.514,0.429) 实测 0.565/0.427（误差 0.051/0.002，倾角 8.1°）；
(0.35,0,0.30)→削到 0.327，实测 0.306（误差 0.021，3.9°）；
(0.20,0,0.40)→削到 0.184，实测 0.147（0.037，2.7°）；
(0.125,0,0.50)→削到 0.118，实测 0.076（0.042，2.5°）；
三轴满量程→(0.046,0.039,0.697)，倾角 **4.1°**（无任何约束时 46.6° 翻车）。

新增 env：`S8_CMDMAX_VX/VY/WZ`（单轴钳位）。场景：`combo_yw.csv`、`combo_3ax.csv`、`combo_bnd.csv`。
#### 超限分配策略定为「同比缩比」（`combo_priority=0`，默认）

竞争项超限后三轴的分配方式做了三态开关：

| 值 | 策略 | 缩放 |
| --- | --- | --- |
| **0（默认）** | 同比缩比 | $k=(\text{budget}/(v_{xy}\omega_z^2))^{1/3}$ |
| 1 | 转向优先 | $k=\text{budget}/(v_{xy}\omega_z^2)$（只削平移） |
| 2 | 平移优先 | $\omega_z\leftarrow\sqrt{\text{budget}/v_{xy}}$（只削转向） |

**why 三次根**：竞争项里 $\omega_z$ 是平方，若三轴同乘 $k$，则 $v_{xy}\omega_z^2$ 变成
$k^3$ 倍，所以 $k$ 取三次根才能刚好压到 budget。

同比缩比的实测（`prio0_max3`、`prio0_bnd`）：

| 请求 | 下发 | 实测 | 相对下发误差 | 倾角 |
| --- | --- | --- | --- | --- |
| (0.60,0.50,1.00) | (0.201, 0.168, 0.335) | (0.125, 0.106, 0.332) | 偏航 0.003 / 平移 0.098 | **8.3°** |
| (0.60,0.50,0) | (0.514, 0.429, 0) | (0.562, 0.420) | 0.048 / 0.009 | 8.2° |
| (0.35,0,0.30) | (0.342, 0, 0.293) | (0.322, 0, 0.293) | 0.020 | 3.8° |
| (0.20,0,0.40) | (0.194, 0, 0.389) | (0.151, 0, 0.391) | 0.043 | 2.4° |
| (0.125,0,0.50) | (0.122, 0, 0.490) | (0.078, 0, 0.488) | 0.045 | 2.5° |

**四个边界点相对「实际下发值」的误差全部 ≤0.05** → 边界可复现。

观察：同比缩比让**偏航精确、平移打折**（三轴极限处约 63%），且低 $\omega_z$ 高 $v_{xy}$
区域模型偏乐观（同样 $v_{xy}\omega_z^2=0.0294$，$(0.342,0.29)$ 实测无损失、
$(0.262,0.335)$ 实测损失 0.098）。说明竞争损失还受**具体转速/方向**影响，单参数模型不够精细；
要更准需要分区域标定表（暂不做）。

**1. 滑移补偿固化 `cmd_vel_trim: 0 → 0.04`**

滑移导致的「机身恒快 ≈0.045 m/s」是 MuJoCo 接触模型特性，与控制器增益无关。
0.04 的取法依据（单轴实测）：

| 轴 | 未补偿（trim=0） | trim=0.04（默认） | 误差变化 |
| --- | --- | --- | --- |
| $v_x$ +0.20 / +0.40 / +0.60 | +0.204 / +0.400 / +0.606 | +0.219 / +0.408 / +0.611 | 0.019 / 0.008 / 0.011 |
| $v_x$ −0.20 / −0.40 / −0.60 | −0.187 / −0.395 / −0.575 | −0.208 / −0.398 / −0.586 | 0.008 / 0.002 / 0.014 |
| $v_y$ +0.10 / +0.20 / +0.30 | +0.118 / +0.227 / +0.284 | +0.100 / +0.217 / +0.274 | 0.004 / 0.020 / 0.030 |
| $v_y$ −0.10 / −0.20 / −0.30 | −0.115 / −0.226 / −0.285 | −0.097 / −0.216 / −0.274 | 0.008 / 0.025 / 0.030 |

注意 $v_x$ 与 $v_y$ 的偏置不是同一个常量（$v_x\approx+0.045$ 各速段恒定，
$v_y$ 0.10 处 ≈+0.05、0.30–0.50 处 ≈+0.012），**单一常量无法同时压平两轴**。
0.04 是折中：$v_x$ 全速段误差 ≤0.019，$v_y$ ≤0.030（低速档会轻微欠速）。
纯 $\omega_z$ 不触发补偿（`vmag>1e-6` 才缩放），已验收的转向行为不受影响。
