# Lite3 运动控制重建计划与进度

> 当前工作表，2026-10-14 重新建立。旧版 S0–S9 记录完整保存在 [旧版实现与试验记录](archive/04_旧版实现与试验记录.md)。旧记录使用过不同的仿真时序、起立方式和参数，不能直接充当新基线的验收结果。已有源码与离线测试可复用，但“测试通过”和“整机控制效果好”是两件事。

## 1. 当前判断与目标

当前 MPC+WBC 控制 Lite3 的实际效果不能满足要求。先把不使用 MPC、WBC、力前馈的开环位置控制调好，再以单变量实验逐层加入反馈和优化器。每一层都要能独立关闭、复现前一层结果，并记录增益、代价和失败场景。根目录 README 继续作为工程入口；本文件记录下一步要做什么、已经做到什么程度。

截至本次重建，源码已有运动学、状态估计、步态、SRBD-MPC、Weighted-QP WBC 和状态机接入，离线 CTest 曾 13/13 通过。这只说明对应程序能构建且离线检查通过。更改通信节拍后，旧版锁步仿真的 12/12 PASS、速度比、滑移值和逐位重复性均属于历史数据，必须重新测量。

## 2. 仿真与数据契约

仿真节拍对齐 /home/robot/pengyingjian/rl_deploy：MuJoCo 由墙钟约每 1 ms 自主执行一步，每步发送状态；C++ 接口的发送线程独立约每 1 ms 发送最近一次关节命令。仿真每步使用最近收到的命令，不等待新命令，也不保证“一观测一命令一步”。控制器按新状态时间戳更新目标；缺帧、重帧、通信延迟需要测量并如实记录。

保持当前 12×5 命令格式，列顺序为 kp、目标角、kd、目标角速度、前馈力矩。开环阶段前馈力矩固定为 0。保持站立初始位姿、足端接触模型和日志选项作为独立配置，任何比较都记录这些配置。仿真与真机的力矩上限、关节顺序和 IMU 单位在进入真机阶段重新核验。

旧版 A/B 脚本可作为采集工具，不能因为分析器输出 PASS 就认定控制质量合格。报告至少同时展示命令与实测速度、位移、机身高度、roll/pitch/yaw、实际电机力矩及饱和、四足接触/离地净空、支撑滑移、停步残余速度、控制周期与观测年龄；保留原始 CSV、参数和代码版本。

## 3. 分层路线与通过条件

| 阶段 | 本阶段只启用的控制层 | 必须验证的内容 | 当前状态 |
| --- | --- | --- | --- |
| R0 时序与模型核对 | 关节 PD 保持站立 | 与参考工程的独立定时收发一致；量测实际仿真步频、状态/命令频率、丢帧和延迟；确认关节方向、力矩限幅、足端接触与初始姿态 | 通信方式已改；测量待做 |
| R1 静态开环 | 固定站姿 + 关节 PD，前馈为 0 | 站立 20 s，目标角与实测角、机身高度、姿态和力矩曲线可解释；起立与控制接管独立验证 | 待重验 |
| R2 运动学步态开环 | 时间步态 + 足端轨迹 + IK + 关节 PD | 单腿抬落、原地踏步，再前/后/左/右/转向；逐腿核对目标与实测足轨迹、摆动离地、支撑滑移、关节限位 | 待重验 |
| R3 开环速度标定 | R2 + 按方向标定步幅/扫掠 | 固定场景至少重复 5 次；分别看前后、侧移、偏航、混合、停步；给出均值、极值与失败率，不用单个总增益掩盖方向差异 | 待做 |
| R4 低层反馈 | 在已验收开环上逐项加入高度、姿态、落足或接触反馈 | 每次只加一项，使用同场景 A/B；若改善一个指标却显著恶化稳定性、滑移或饱和，回退该项 | 待做 |
| R5 模型与估计 | 逐项启用状态估计、M/h/J 和接触判断 | 先与 MuJoCo 真值对表，再在新时序闭环中核对估计误差与失效标志；真值只用于诊断 | 待重验 |
| R6 力控制 | 在 R4/R5 基线上先加可关闭的力前馈，再引入 MPC 或 WBC | 分别证明力命令经 12×5 接口正确作用、摆动足实际离地、支撑力与力矩限幅一致；逐层比较净收益 | 待做 |
| R7 MPC+WBC 集成 | 已独立验证的优化器组合 | 站立、行走、停步、换向、长时间与扰动场景均需复测；记录求解失败、旧解年龄、实时截止时间 | 待做 |
| R8 真机迁移 | 经过 R0–R7 验证的控制链 | SDK 映射、控制权、关节/IMU 单位、实际电机限幅、保护状态与急停逐项核对，低速逐级扩大包线 | 待做 |

R1–R3 是当前唯一的调试主线。现有 MPC/WBC 文件保留用于后续分层复用，但不作为开环调参的隐藏依赖。每阶段先冻结测试场景与评价口径，再改控制参数；具体数值门槛应根据 R0/R1 的实测噪声和安全余量确定，不沿用旧版 PASS 阈值。

## 4. 当前可运行入口

开环控制器为 mpc_wbc/apps/position_loop_sim.cpp；场景位于 mpc_wbc/test/scenarios/。可用 mpc_wbc/test/run_s4_position_loop.sh 做无头开环采集，或用 mpc_wbc/test/run_s9_ab.sh --baseline --only <场景名> 跑单场景。优化器路径位于 mpc_wbc/apps/mpc_wbc_sim.cpp 和 state_machine/mpc_control_state.hpp，R6 之前只做回归检查，不作为调参目标。

离线模型检查可运行：cmake -S . -B build -DBUILD_MPC_WBC_TESTS=ON -DBUILD_MPC_WBC_SIM=ON；cmake --build build -j；ctest --test-dir build --output-on-failure。闭环测试需要单独启动 MuJoCo，不能由离线 CTest 代替。

## 5. 迭代记录模板

每次完成一项后，在本节追加记录，不覆盖旧数据：

- 日期、Git 提交、改动文件与唯一变化的参数/算法；
- 仿真模型、接触模式、初始位姿、场景、命令和重复次数；
- 改动前后同口径指标：速度/位移、姿态/高度、离地净空、滑移、饱和、求解/通信耗时、失败率；
- 结论：通过、未通过或证据不足；明确下一步和回退办法。
