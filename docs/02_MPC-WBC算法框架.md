# Lite3 运动控制分层框架（重建版）

> 本文定义后续实现的结构和数据契约，不宣称现有 MPC+WBC 已达到预期控制效果。执行顺序与验收状态见 [重建计划](04_Lite3_MPC_WBC实现步骤与里程碑.md)；旧版试验只作参考。

## 1. 控制目标与约束

对象是 12 个驱动关节的 Lite3，先在平地验证静立、前后、左右、原地转向、混合命令及停步，再扩大速度、时长和扰动范围。ONNX 与模型控制在一次运行中互斥。仿真与真机共用 12×5 关节命令：每行依次为 kp、q_des、kd、dq_des、tau_ff。执行器总力矩按 kp(q_des−q)+kd(dq_des−dq)+tau_ff 理解；仿真实际力矩还受 MJCF 执行器限幅约束。

当前调试从 tau_ff=0 的位置环开始。MPC、WBC、力分配和其他反馈应以独立开关加入，每项都必须能退回最近一次已验收的基线。源码中已有的优化器是可复用候选，不能因为离线 QP 可解就直接视为控制效果可靠。

## 2. 时间与通信

仿真对齐参考 rl_deploy 的独立节拍：MuJoCo 按墙钟约每 1 ms 步进、每步发送观测；C++ 接口独立约每 1 ms 发送最近的关节命令。两端通过 UDP 异步通信，仿真在某一步使用的是该步开始前最近收到的命令。控制器可以按观测时间戳避免重复推进内部状态，但仿真不等待控制器。测试必须记录实际状态与命令频率、缺帧、重复帧、命令年龄和最坏延迟；重复实验需要统计分布，不能要求逐位相同。

项目仍保留可配置的初始站姿、接触模式、场景命令和诊断日志。这些是实验条件，与是否锁步是不同问题。比较不同控制层时必须保持模型、初始位姿、命令和分析口径一致。

## 3. 坐标与接口契约

- 世界系 W：z 向上；机体系 B：x 向前、y 向左、z 向上。
- 腿顺序 FL、FR、HL、HR；每腿关节顺序 HipX、HipY、Knee。
- 广义速度顺序为世界系基座线速度 3 维、机体系角速度 3 维、关节速度 12 维；动力学和 MuJoCo 对表使用同一约定。
- 足端轨迹标注球心还是球足触地点；使用雅可比、接触力或落地高度时须保持一致。
- 状态估计不得把 MuJoCo 真值当作在线输入。仿真真值只用于对表和离线诊断。

## 4. 从简单到复杂的控制链

| 层 | 输入 → 输出 | 在进入下一层前要回答的问题 |
| --- | --- | --- |
| 静态关节 PD | 站姿关节角 → 12×5 命令，tau_ff=0 | 关节方向、站高、限幅和接管是否正确？ |
| 时间步态与 IK | 三轴速度命令、相位 → 四足球心轨迹 → q_des | 摆动脚是否实际离地，支撑脚是否拖地或滑移？ |
| 开环速度标定 | 不同方向的命令 → 步幅/扫掠参数 | 前后、侧移、转向是否各自跟踪，是否牺牲姿态和摩擦？ |
| 低层反馈 | 关节与 IMU → 高度/姿态/落足修正 | 每个反馈项是否在同场景改善整体指标？ |
| 状态估计 | IMU、关节、可信接触 → 基座速度/高度/有效性 | 计划接触与实际接触不符时会怎样？ |
| 力控制与优化 | 估计状态、接触计划、目标运动 → 足力与关节力矩 | 力通道、约束、求解时间和降级行为是否与实测一致？ |

开环阶段先验证固定姿态，再验证单腿和原地踏步，最后进行三轴运动与停步。优化器的引入顺序由实验结果决定；候选路径是力前馈、SRBD-MPC、Weighted-QP WBC，逐个启用与比较，避免一次更换整条链路而无法归因。

## 5. 现有数学模块的复用边界

运动学模块提供 FK、IK、足端雅可比；全身模型提供 M(q)、h(q,qdot)、Jc 和接触偏置加速度。SRBD 模块以质心与姿态近似预测接触力；WBC 模块求解包含广义加速度、逐脚力和关节力矩的 QP。这些模块已有离线测试，是后续工作的地基。在线控制还需重新验证接触状态、软接触下的高度偏差、摆动离地、力矩饱和、输入时延、求解超时和模型误差。

控制周期中的故障处理保持明确：无有效观测、接触不可信、优化器失败、解过期或姿态超限时，要记录原因和发出的实际 12×5 命令。降级控制本身也要在仿真中单独测试，不能只通过代码分支检查验收。

## 6. 实验与记录

先固定仿真模型、初始位姿、命令场景和观测指标，再做单变量 A/B。每个方向至少记录多次运行的均值、极值和失败次数；运动段与站立/接管段分开分析。采集命令与实测关节、IMU、基座真值、四足轨迹及接触、未限幅与实际力矩、控制周期与优化求解时间。指标包括速度误差、位移、姿态、高度、摆动净空、支撑滑移、饱和、停步残余运动和失败率。
